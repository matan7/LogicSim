# 8-bit computer example

`Assets/Resources/Examples/8-bit-computer.json` (Open > Examples > *8 bit computer*) is a small stored-program computer
built only from gates and D flip-flops: 1,411 gates in 12 IC definitions. It is generated by
`Tools/generate_8bit_computer.py` (plain Python 3); change the program there and run it again:

```
python Tools/generate_8bit_computer.py
```

## Top level

- **clock**, **Run** (switch) and **Step** (button) make the clock; **HALT** lights after a `HLT` instruction, which
  stops the clock. Stopping and starting the simulation resets the computer and reloads the program.
- **CPU** and **RAM** chips connected by the data lines (`DOUT` to `D`, `O` to `DIN`), the address (`ADDR`) and the
  write and read enables (`WE`, `OE`).
- Displays: **Output** (the OUT register, hexadecimal), **Bus** and **PC**; lamps **T0** to **T4** show the step of the
  current instruction.

Open the CPU (double-click it while the simulation runs) to see its registers, ALU, bus and control unit with their own
displays; the RAM shows its 16 bytes.

## Inside

| Part | IC | What it is |
|---|---|---|
| Bus | 8 OR gates in the CPU | Each source drives it through AND gates (`driver8`, `driver4`), only one at a time |
| A, B, IR, OUT | `reg8` | 8 D flip-flops; `LOAD` chooses between the bus and the stored value |
| PC | `pc4` | 4-bit counter: counts with `CE`, loads the bus with `J` |
| MAR | `reg4` | Memory address |
| ALU | `alu8` | 8 full adders; `SUB` inverts B and sets the carry in (two's complement) |
| Steps | `steps` | Ring counter T0 to T4 (four flip-flops and a NOR) |
| Control | `control` | Decodes the opcode and the step into the control signals below |
| RAM | `ram16`, `ram-byte` | 16 bytes, address decoder, output multiplexer; each byte reads `Q xor I` with constants `I`, so the flip-flops (all 0 after a reset) start with the program |

Control signals: `CO` PC out, `MI` MAR in, `RO` RAM out, `RI` RAM in, `II` IR in, `IO` IR operand out, `CE` count,
`J` jump, `AI`/`AO` A in/out, `BI` B in, `EO` ALU out, `SU` subtract, `OI` output in, `HLT` halt.

## Instructions

An instruction is one byte: opcode in the high nibble, address or number in the low nibble. Every instruction takes
five clock cycles: T0 `CO MI`, T1 `RO II CE` (fetch), then:

| Instruction | Code | T2 | T3 | T4 | Effect |
|---|---|---|---|---|---|
| `LDA a` | `1a` | `IO MI` | `RO AI` | | A = RAM[a] |
| `ADD a` | `2a` | `IO MI` | `RO BI` | `EO AI` | A = A + RAM[a] |
| `SUB a` | `3a` | `IO MI` | `RO BI` | `EO AI SU` | A = A - RAM[a] |
| `STA a` | `4a` | `IO MI` | `AO RI` | | RAM[a] = A |
| `LDI n` | `5n` | `IO AI` | | | A = n (0 to 15) |
| `JMP a` | `6a` | `IO J` | | | jump to a |
| `OUT` | `E0` | `AO OI` | | | output = A |
| `HLT` | `F0` | `HLT` | | | stop the clock |
| `NOP` | `00` | | | | nothing |

There are no flags, so no conditional jumps; results wrap around at 256.

## Program

The RAM starts with a Fibonacci loop that prints 0, 1, 1, 2, 3, 5, 8, 13, 21, ... (hexadecimal on the Output display):

| Address | Byte | Instruction |
|---|---|---|
| 0 | `51` | `LDI 1` |
| 1 | `4E` | `STA 14` (x = 1) |
| 2 | `50` | `LDI 0` |
| 3 | `4F` | `STA 15` (y = 0) |
| 4 | `E0` | `OUT` (print y) |
| 5 | `2E` | `ADD 14` |
| 6 | `4D` | `STA 13` (t = y + x) |
| 7 | `1E` | `LDA 14` |
| 8 | `4F` | `STA 15` (y = x) |
| 9 | `1D` | `LDA 13` |
| 10 | `4E` | `STA 14` (x = t) |
| 11 | `1F` | `LDA 15` |
| 12 | `64` | `JMP 4` |
| 13-15 | `00` | t, x, y |

To change it in the app, open the RAM: each byte `M0` to `M15` has a row of eight constants (bit 7 on the left); select
one and press its value in the inspector.

## Timing

The simulation is unit-delay: every gate takes one tick. The longest path, through the ripple-carry adder, needs about
14 ticks, so the computer works with a clock half period of 8 ticks or more; the example uses 20. At the default 600
ticks/s that is a 15 Hz clock, about three instructions per second.
